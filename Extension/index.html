ADO Automation Tool

The ADO Automation Tool is a powerful web API designed to automate your Azure DevOps workflows. It listens to webhooks and executes C# scripts to enforce rules, sync data, or perform complex logic that goes beyond standard policies.

Note: This extension provides documentation and guidance. The automation engine itself must be deployed separately (e.g., via Docker).

1. Configuration

To trigger your automation scripts, you need to configure Service Hooks in this project to point to your deployed tool.

1. Go to Project Settings > Service Hooks.
2. Click the + button to create a new subscription.
3. Select Web Hooks and click Next.
4. Choose a trigger event (e.g., Work item updated) and set filters. Click Next.
5. In the Action settings:
  • URL: Enter the URL of your deployed tool (e.g., https://your-tool-instance.com/WebHook).
  • HTTP Headers: If you configured a shared key, add it here (e.g., X-Shared-Key: your-secret-key).

2. Writing Rules

Scripts are C# files (.rule) that are executed when an event occurs. You have direct access to the Work Item context.

Available Context Objects

  • Self: The current Work Item object. You can read and modify fields directly.
  • SelfChanges: A dictionary containing only the fields that changed in this event.
  • Client: The Azure DevOps client for fetching other items, saving changes, or querying data.
  • Logger: Use this to write logs to the tool's output.

Example Script

// Log the event
Logger.Information($"Processing Work Item {Self.Id}: {Self.Title}");

// Update a field automatically
Self.Fields["System.Description"] = $"Updated by automation at {DateTime.Now}";

// Check parent details
if(Self.Parent != null) {
    var parent = await Client.GetWorkItem(Self.Parent.RelatedWorkItemId);
    Logger.Information($"Parent Title: {parent.Title}");
    
    // Logic based on parent state
    if (parent.State == "Closed") {
        Logger.Warning("Parent is closed!");
    }
}

3. Scheduled Scripts

In addition to webhooks, the tool supports Scheduled Scripts for periodic tasks (e.g., nightly syncs, cleanup).

  • Scripts run on a configurable interval (default: 1 hour).
  • Access to LastRun time allows for incremental processing.
  • Scripts can return a custom interval for the next run.
